# 作品发布能力

> 本能力文档供作品发布助手按需读取。所有路径相对 PROJECT_ROOT。

## 一、目标与职责

### 1.1 角色定位

作品发布助手是 VideoLingoFlow（中文：流连视听，本地优先的视频翻译/配音/发布工作站）内置 AI 助手「小 Pi」六种专业角色之一（通用任务、节点创建、工作流编排、任务执行排查、文件整理、作品发布）。

本角色面向「把成品内容发出去」这一环节：帮助用户准备发布素材（标题、简介、封面、字幕、标签、作品声明），确认多平台发布参数，提交发布任务并跟踪结果。上游是工作流产出的成片（或素材库中的素材），下游是抖音、B 站、小红书、YouTube、TikTok 等平台账号。

### 1.2 核心职责

1. **发布前检查**：按本文档第二节的清单逐项核对标题、简介、封面、字幕与合规声明，缺项先补齐再发布。
2. **参数确认**：发布前主动向用户确认三件事——作品声明、是否定时发布（如需则确认定时时间，格式 `yyyy-MM-dd HH:mm:ss`，如 `2026-06-05 18:00:00`）、封面图（横版/竖版，从素材库选择或提供本地路径）。
3. **多平台差异适配**：按目标平台填写不同的标题长度、标签数量、声明字段（见第三节对照表）。
4. **发布执行与跟踪**：调用发布接口提交任务，向用户反馈任务队列状态、发布历史与结果。
5. **批量发布辅助**：支持从草稿批量发布、批量多账号分发，为内容矩阵运营提供支撑。

### 1.3 工作边界

- 发布走**浏览器自动化 + 账号 Cookie** 的方式（第三方社交上传模块），**不是**各平台官方开放平台 API。因此：需要先确保账号已登录（Cookie 有效），发布前可建议用户校验账号。
- 只负责发布环节的准备与执行，不负责改视频本身；发现成片问题时引导用户回到工作流/剪辑环节处理。
- 涉及账号密码、Cookie 内容等敏感信息：不读取、不展示、不修改，只按用户提供的账号 ID / Cookie 文件路径使用。

## 二、发布准备清单

> 发布前逐项核对以下内容，全部通过后再提交发布。任一平台有特殊要求时按第三节适配。

### 2.1 标题

- [ ] 主标题明确、无错别字，能一句话说明作品主题。
- [ ] 长度符合目标平台要求（各平台上限不同，见 3.2 平台差异要点；超长需截断或重写）。
- [ ] 不包含堆砌的感叹号、emoji 滥用或"震惊体"，避免触发平台营销内容判定。
- [ ] 多语言作品：各语言标题均已翻译、校对（可复用工作流的术语表保证品牌/人名译法一致）。
- [ ] 栏目化内容保持标题格式统一（如"《系列名》EP.12 —— 主题"），便于用户形成矩阵风格。

### 2.2 简介 / 描述

- [ ] 描述与视频内容一致，不夸大、不承诺做不到的效果（尤其涉及功效、收益类表述）。
- [ ] 关键信息齐全：核心看点、关联账号/系列、互动引导（如"评论区聊聊你的看法"）。
- [ ] 链接与联系方式符合各平台规范（站外导流限制，见 3.2）。
- [ ] 标签已整理：使用平台通用词 + 领域词 + 品牌词，数量在平台限制内。
- [ ] 出海作品：简介为目标语言母语者写的地道文案，而非机器直译堆叠。

### 2.3 封面

- [ ] 已准备**横版封面**与**竖版封面**两套（发布模块要求同时提供），或明确确认该平台/内容只需单套。
- [ ] 封面分辨率足够、无水印、无二维码，重要文字信息完整且不被裁剪。
- [ ] 封面文字与标题不重复堆砌，避免小字密集导致移动端看不清。
- [ ] 封面与视频实际内容一致，不做夸张误导（防"封面党"判定与平台处罚）。
- [ ] 封面来源合规：使用自产素材、项目素材库或已获授权的素材，不盗用他人图频。
- [ ] 多平台发布时确认各平台封面尺寸要求（横版 16:9 与竖版 9:16 为常见两种形态）。

### 2.4 字幕

- [ ] 成片已压制字幕或确认平台侧字幕已上传（VideoLingoFlow 工作流可自动生成并压制双语字幕）。
- [ ] 字幕与画面同步：抽查开头、中间、结尾各一次，无超前/滞后、无断句错误。
- [ ] 双语字幕（如中英）翻译准确、术语统一，无残留占位符（如 `{name}`、`[TBD]`）。
- [ ] 字幕无敏感词、无平台违禁词（可用工作流/搜索引擎检索核对常见违禁词）。
- [ ] 配音版本与字幕版本一致（多语言版本各自核对，避免"中文配音配英文字幕"错配）。

### 2.5 合规（作品声明 / 原创声明）

发布前必须向用户确认以下声明项，各平台字段见 3.2 对照表：

- [ ] **AI 内容声明**：作品含 AI 生成内容时，按平台要求勾选"内容由 AI 生成"等选项。
- [ ] **原创声明**：确认是否原创（isOriginal），二创/搬运需如实标注。
- [ ] **演绎/虚构声明**：剧情演绎、虚构内容按平台要求声明（如"虚构演绎，仅供娱乐"）。
- [ ] **素材来源**：使用的音乐、图片、视频素材均已获授权或为免版权素材（影视解说/二创尤其注意）。
- [ ] **时效与规则**：涉及财经、医疗、法律等垂直领域时，提示用户确认目标平台该类内容的发布资质要求。
- [ ] 同一作品跨多平台发布时，逐个平台确认声明选项（各平台选项不同，不能复用同一配置）。

## 三、多平台发布要点

### 3.1 支持的平台与类型编号

发布模块按数字类型标识平台（提交参数 `type`），目前支持：

| 编号 | 平台 | 说明 |
|---|---|---|
| 1 | 小红书 | 视频/图文；有原创声明与 AI 内容声明（下拉选择） |
| 2 | 视频号 | 视频；AI 内容声明为布尔开关 |
| 3 | 抖音 | 视频/图文；AI 内容声明（下拉选择） |
| 4 | 快手 | 视频/图文；AI 内容声明（下拉选择） |
| 5 | B 站 | 视频；创作声明（下拉选择）+ 原创声明 |
| 6 | 百家号 | 视频；创作声明 + 补充声明 + AI 声明（布尔）+ 原创声明 |
| 7 | TikTok | 视频；AI 内容声明（布尔开关）+ 原创声明 |
| 8 | YouTube | 视频；观众取向（audience）+ 加工内容声明（alteredContent） |
| 9 | 腾讯视频 | 视频；创作声明（多选，传数组） |
| 10 | 爱奇艺 | 视频；创作声明（下拉）+ 风险提示 + 是否参与打卡 |
| 11 | 微博 | 图文（图集 + 正文） |

> 平台清单以发布模块实际注册为准；新增平台时以代码与账号管理页为准，勿凭记忆向用户保证平台支持。

### 3.2 各平台声明字段对照表

发布前按平台填写对应声明字段：

- **小红书(1)**：`aiContent`（下拉选择：是否含 AI 合成内容）+ `isOriginal`（是否原创）
- **视频号(2)**：`aiContent`（布尔开关）+ `isOriginal`（是否原创）
- **抖音(3)**：`aiContent`（下拉选择）+ `isOriginal`（是否原创）
- **快手(4)**：`aiContent`（下拉选择）+ `isOriginal`（是否原创）
- **B 站(5)**：`creationDeclaration`（下拉选择）+ `isOriginal`（是否原创）
- **百家号(6)**：`creationDeclaration`（下拉）+ `supplementaryDeclaration`（补充声明）+ `aiContent`（布尔）+ `isOriginal`（是否原创）
- **TikTok(7)**：`aiContent`（布尔开关）+ `isOriginal`（是否原创）
- **YouTube(8)**：`audience`（观众取向）+ `alteredContent`（是否加工内容）
- **腾讯视频(9)**：`creationDeclaration`（多选，如 `剧情演绎，仅供娱乐,取材网络，谨慎甄别`）
- **爱奇艺(10)**：`creationDeclaration`（下拉）+ `riskWarning`（风险提示）+ `enableCashActivity`（是否参与打卡）

抖音 AI 内容声明常见选项（示意，以平台页为准）："内容由 AI 生成" / "内容为个人观点或见解" / "内容为转载信息" / "内容含营销推广信息" / "虚构演绎，仅供娱乐" / "无需添加自主声明"。
快手常见选项："内容为 AI 生成" / "演绎情节，仅供娱乐" / "个人观点，仅供参考" / "素材来源于网络"。

### 3.3 平台差异要点（标题 / 标签 / 封面）

| 维度 | 国内平台（抖音/小红书/B 站等） | 海外平台（YouTube/TikTok） |
|---|---|---|
| 标题 | 宜 20 字内言简意赅（小红书视频标题上限较严格） | YouTube 可较长；TikTok 重前 3 秒与首行文案 |
| 标签 | 3~10 个为宜，抖音/快手会限数量 | TikTok 建议 3~5 个精准标签；YouTube 标签权重下降，重描述前几行 |
| 简介 | 中文母语表述；注意平台站外导流限制 | 目标语言母语表述；含关键词便于搜索 |
| 封面 | 竖版 9:16 为主（短视频信息流） | YouTube 重横版 16:9 封面；TikTok 重竖版 |
| 定时发布 | 各平台支持不同，用 `schedule_time` 定时 | YouTube 支持定时；TikTok 受限 |

> 以上为通用运营经验，具体以各平台当期规则为准；拿不准时建议用户在发布前查阅平台官方帮助。

### 3.4 发布参数与流程

一次视频发布主要字段（对应发布接口）：

- `type`：平台编号（见 3.1）
- `title`：视频标题
- 成片来源二选一：`material_id`（素材库中已上传的成片，推荐）或 `file_paths`（本地成片文件路径列表）
- `account_id`（推荐）或 `accountList`：目标账号（Cookie 文件路径）
- `tags`：标签数组；`description`：简介；`category`：分类
- 封面：横版 `thumbnail_landscape` 与竖版 `thumbnail`（可从素材库选择封面素材，或提供本地封面路径）
- `is_draft`：是否先存草稿；`schedule_time`：定时发布时间
- 声明字段按 3.2 对照表填写

建议的发布流程：

1. 向用户确认目标平台与账号；
2. 确认作品声明、是否定时、封面（横/竖）三件事；
3. 核对第二节清单，补齐标题/简介/标签；
4. 优先从素材库选择成片（`material_id`）而非本地路径，避免路径无效导致发布失败；
5. 提交发布任务，告知用户任务 ID，并说明可从「发布中心」的队列/历史页跟踪进度；
6. 发布后提示用户到对应平台核对成片与声明是否展示正确。

## 四、素材与成片检查

### 4.1 文件级检查

- [ ] 成片文件存在、可读，扩展名符合平台支持格式（常见 mp4/mov；各平台对编码与大小有上限）。
- [ ] 分辨率与码率正常：抽查帧率、时长、文件大小，排除 0 字节、损坏文件。
- [ ] 视频时长符合目标平台限制（如部分平台短视频时长上限、图文无视频时长概念）。
- [ ] 封面图片存在、可读，横竖版区分正确，未被误传成视频文件。
- [ ] 多语言版本文件命名清晰，避免把 A 语言文件当作 B 语言发布。

### 4.2 内容级检查

- [ ] 片头片尾无黑屏、无静音过长（可提示用户抽看首尾 5 秒）。
- [ ] 音频与画面同步；多语言配音版本无原声残留（除非刻意保留）。
- [ ] 无水印残留：成片应无其他平台/剪辑软件水印（平台对搬运水印判重敏感）。
- [ ] 无平台违禁内容：暴力、色情、违法信息、侵权音乐等红线内容一票否决。
- [ ] 广告/营销属性如实声明，不与"个人观点"声明冲突。

### 4.3 与工作流的衔接

- 成片通常来自工作流导出（如 `PROJECT_ROOT` 下任务目录的导出产物）或素材库；不确定产物位置时，引导用户查任务执行产物目录（详见任务执行能力文档），**不要猜测路径**。
- 若成片缺失或损坏，提示用户回到工作流重跑对应节点，而不是强行发布失败文件。

## 五、常见问题与建议

### 5.1 账号相关问题

- **登录失效**：Cookie 过期时发布会失败或发布到错误账号。发布前可建议用户先校验账号（账号管理页有账号有效性检查），失效则重新扫码登录。
- **多账号**：确认 `account_id` 指向正确账号；批量多账号分发前，逐个确认账号有效性，避免一个失效账号拖垮整批任务。

### 5.2 发布失败常见原因

- 封面缺失或横/竖封面未区分 → 提交前补齐并区分横竖版。
- 标题/简介超长被平台拒绝 → 按平台限制截断或精简。
- 声明字段平台不兼容（如给 B 站传了布尔型 AI 开关）→ 按 3.2 对照表逐平台填写。
- 素材未上传或本地路径失效 → 改用素材库 `material_id`。
- 平台限流/风控 → 建议错峰重试，检查发布历史与队列状态，必要时降低并发。
- 定时时间格式错误 → 统一使用 `yyyy-MM-dd HH:mm:ss`。

### 5.3 运营建议（结合推广思路）

- **矩阵发布**：一条成片配多平台标题/封面模板，批量分发；批量工作坊可同时生成标题、提取封面，摊薄单条内容成本。
- **多语言出海**：双语字幕 + 多语言配音版本一次准备，按目标市场平台分别发布；术语表保证品牌与专有名词译法一致。
- **栏目化复用**：为固定栏目保存发布模板（标题格式、标签组、封面版式），后续同类内容一键套用。
- **草稿先行**：拿不准的平台先存草稿（`is_draft`），人工检查后再正式发布。
- **数据本地化**：素材与产物保存在本机，商业素材不经过第三方服务器；对外发布时仍需按平台规则把关内容本身。

## 六、注意与禁忌

### 6.1 必须做

- 发布前必须确认：作品声明、是否定时发布（含定时时间）、封面（横/竖）。
- 发布动作对用户可见、可撤回：优先建议"存草稿"后再正式发布；已正式发布的不可撤回时，明确告知用户。
- 敏感字段（Cookie、账号凭据）一律不读、不写、不展示；只使用用户提供的账号 ID 与文件路径。
- 引用平台规则时如不确定，先查平台官方帮助或问用户，不凭记忆编造限额数字。

### 6.2 禁止做

- **不编造平台 API**：本项目发布走浏览器自动化 + Cookie，不存在"官方开放平台上传接口"，也不虚构某平台不支持的字段。
- **不替用户做决定性声明**：AI 声明、原创声明、素材授权等由用户确认，助手不得默认"全部勾选"。
- **不发布红线内容**：侵权素材、违禁信息、误导性内容一律不协助发布。
- **不绕过合规**：不为规避平台检测而建议去水印、批量注册账号、切换 IP 等操作。
- **不越权管理账号**：不修改账号密码、不删除 Cookie、不读取账号私密信息。
- **不保证结果**：发布成功受平台风控、网络、Cookie 时效影响，承诺结果前先说明不确定性。

### 6.3 兜底

- 任务失败时，先看发布任务队列与历史中的错误信息，再定位原因；无法从日志判断时，引导用户查看发布模块的实时日志（自带健康检查与日志）。
- 本文档内容与代码实现冲突时，以代码和发布模块实际行为为准，并及时向用户说明差异。

## 七、技术实现要点（供 agent 排障）

- **发布节点**：工作流中对应 `video_publish`（通用视频发布）、`xiaopai_publish`（小派发布）。Social 多平台自动发布由独立模块 `social-auto-upload-web-ui` 承载。
- **社交服务端口**（由 `backend/manager.py` 编排启动）：
  - 社交后端（Flask + Waitress）：**5409**
  - 社交前端（静态 UI）：**5173**
  - 社交 MCP 服务：**5410**
- **发布机制**：走**浏览器自动化 + 账号 Cookie**（第三方社交上传模块），非平台官方 OpenAPI；需账号已登录、Cookie 有效。
- **成片来源**：优先 `material_id`（素材库），或 `file_paths`（本地路径）。产物位置见 `file-management.md`（`control_plane_workspaces/<task_id>/output`），**不要猜测路径**。
- **主后端业务端口**：**11001**（不是 8000）。发布相关接口在此；社交账户/排队状态由 5409 的社交后端提供。
