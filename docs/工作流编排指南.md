# 工作流编排指南

> 本文档指导智能体（Agent）根据用户需求**自助编排工作流**：工作流的书写格式、存放位置、可用节点清单。
> 所有约定均以当前代码库真实实现为准（控制平面 + Celery 架构，工作流 = 节点 + 连线的有向无环图 DAG）。

---

## 1. 工作流是什么

工作流是一个 **DAG（有向无环图）**：由若干**节点**（node）和**连线**（edge）组成。

- **节点**：一个具体处理步骤，如「音频分离」「语音识别」「逐句翻译」「字幕烧录」。
- **连线**：数据从上游节点的**输出端口**流向**下游节点的输入端口**，端口类型必须兼容。
- **执行**：从 `input` 节点开始，按依赖顺序依次执行；每个节点读取上游产物、产出新产物，进度/结果实时写入任务。

> 一句话：**工作流 = 数据从「输入」流向「输出」的处理管线**。

---

## 2. 存放位置

| 项 | 位置 |
|---|---|
| 用户工作流文件 | `backend/config/workflows/{wf_id}.json`（`type: "user"`） |
| 全局工作流固定调试任务 | 控制平面 DB（`payload.is_debug=True`），工作区 `control_plane_workspaces/{task_id}/`（不要手写） |
| 一般/批量任务私有工作流快照 | `control_plane_workspaces/{task_id}/workflow.json`（执行/保存时自动写入，不要手写） |
| 任务执行目录 | `control_plane_workspaces/{task_id}/`（`cache/`、`output/`、`workflow.json`、`task.json`） |
| 内置节点定义（只读） | `backend/config/builtin_node_types.py` |
| 自定义节点定义 | `backend/config/node_types/{node_id}.json`（节点管理器创建/导入） |
| 自定义节点代码目录 | `backend/nodes/{node_id}/`（python 类型节点） |

**工作流文件是 JSON**，文件名即工作流 id（不含 `.json`）。前端「工作流编排」页面可加载、编辑、保存、执行这些文件。
**任务与工作流解耦**：全局工作流绑定一个固定调试任务（`is_debug`），一般任务/批量子任务各自持有私有工作流快照，互不影响（详见《工作流运行指南》第 2 节）。

## 3. 工作流 JSON 书写格式

### 3.1 顶层结构

```json
{
  "id": "my_workflow_id",
  "name": "我的工作流",
  "description": "一句话描述",
  "type": "user",
  "nodes": [ ...节点数组... ],
  "edges": [ ...连线数组... ],
  "createdAt": "2026-08-09T00:00:00.000Z",
  "updatedAt": "2026-08-09T00:00:00.000Z"
}
```

- `type` 必须是 `"user"`（`"task"` 是任务内部快照，不要手写）。
- `id` 全局唯一、小写字母/数字/下划线。

### 3.2 节点（nodes）书写格式

```json
{
  "id": "n_001",
  "type": "workflow",
  "position": { "x": 0, "y": 0 },
  "data": {
    "nodeType": "extract_audio",
    "label": "音频分离",
    "config": { "format": "wav", "sample_rate": "44100" }
  }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | **画布内唯一**节点 id（`n_` 前缀，任意字符串均可，供连线引用） |
| `type` | 固定 `"workflow"` |
| `position` | 画布坐标，仅排版用，任意值即可 |
| `data.nodeType` | **节点类型 id**（即可用节点清单里的 id，见第 5 节） |
| `data.label` | 画布显示名 |
| `data.config` | 该节点的配置字典（key 必须是节点定义 `configFields` 中的 key，见第 5 节） |

### 3.3 连线（edges）书写格式

```json
{
  "id": "e_001",
  "source": "n_001",
  "target": "n_002",
  "sourceHandle": "out-audio",
  "targetHandle": "in-video",
  "data": { "sourcePort": "audio", "targetPort": "video" }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `source` / `target` | 上游 / 下游节点 id（必须存在于 nodes） |
| `sourceHandle` | `"out-" + 上游节点的输出端口 id` |
| `targetHandle` | `"in-" + 下游节点的输入端口 id` |
| `data.sourcePort` / `data.targetPort` | 端口 id 冗余字段（前端写入，后端校验时也会重新规范化） |

> 连线端口命名规则：**输出端口 `out-<端口id>`，输入端口 `in-<端口id>`**，端口 id 见第 5 节节点清单。

## 4. 端口类型与连线规则

### 4.1 端口类型（PortType）

| 类型 | 含义 | 典型来源 |
|---|---|---|
| `video` | 视频文件 | input 节点视频、下载、合成结果 |
| `audio` | 音频文件 | 提取/分离/合并结果 |
| `audio_manifest` | 音频清单 JSON | 配音任务单 |
| `json` | JSON 数据文件 | ASR 结果、翻译结果、任务单等 |
| `pandas` | 表格数据 | TTS 任务表 |
| `subtitle` | 字幕文件 | 字幕生成结果 |
| `text` | 文本文件 | 标题、prompt、LLM 结果 |
| `image` | 图片文件 | 封面、帧图、水印图 |
| `url` | URL 字符串 | input 节点 url、下载输入 |
| `preview` | 预览 | 预览节点内部 |
| `any` | 通用 | 可连接任何类型 |

### 4.2 连线规则

- **相同类型才能连线**：`video→video`、`audio→audio`、`json→json`、`subtitle→subtitle`、`text→text`…（`canConnect` 校验）。
- **`any` 是万能端口**：`any` 可连任意类型。
- 后端保存时 `normalize_workflow` 会校验每条边：端口不存在或类型不匹配的边会被**直接删除**（保存后边数可能减少）。
- 一个输出端口可连多个下游；**同一输入端口不要连多条边**（后写入的会覆盖）。

## 5. 可用节点清单（40 个内置节点）

> 分类对应前端节点面板；`执行域`：`thread`（线程内，轻量）/ `process`（子进程隔离，重型/网络，可硬停止）。
> `config` 只列关键项，全部可选字段以节点定义 `configFields` 为准（默认值可省略不写）。

### 5.1 输入 / 输出 / 预览

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `input` | 输入 | （数据源）→ `video`/`audio`/`subtitle`/`url` | `selectedTypes`(chips: video/audio/subtitle/url)、`videoPath`/`audioPath`/`subtitlePath`/`url`、`source_language`/`target_language`、`copyInputs`(复制到 cache/input_video.*)、`var1`/`var2` |
| `output` | 输出 | `any` → （无） | `outputDir`、`fileName`、`suffix`、`autoIncrement` |
| `video_preview` | 视频预览器 | `video`/`subtitle`/`original`/`bilingual` → （无） | 仅预览，无执行 |
| `image_preview` | 图片预览器 | `image` → （无） | 仅预览，无执行 |

### 5.2 下载 / 工具类

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `platform_download` | 平台视频下载 | `url` → `video`/`subtitle`/`image` | `download_subs`、`download_cover`、`resolution`(best/1080p/720p)、`cookie_file`、`use_as_task_name` |
| `path_to_title` | 路径转标题 | `any` → `text` | `read_from_input`、`template`(占位符 {filename}/{parent}/{grandparent})、`update_task_name` |
| `file_rename` | 文件改名 | `any` → `any` | `rename_mode`(custom/prefix/suffix)、`custom_name`/`prefix`/`suffix` |
| `resolve_path` | 取文件路径 | `any` → `any` | `relative_path`(如 `output/video.mp4`、`cache/subtitle.srt`) |
| `json_to_text` | JSON转文本 | `json` → `text` | `mode`(full/key)、`key_expr`(key0$key1$key2) |
| `json_editor` | JSON编辑 | `json`/`text` → `json` | `key_expr`、`value_source`(auto/input/custom)、`custom_value` |
| `video_split` | 视频切割 | `video`/`audio` → `video`/`text` | `split_mode`(count/duration)、`segment_count`、`segment_duration`、`use_silence` |
| `timed_delay` | 定时执行 | `any` → `any` | `delay_mode`(time_point/countdown)、`target_date`/`target_time`、`countdown_hours/minutes/seconds` |
| `translate_task_name` | 翻译项目名称 | `any` → `text` | `replace_task_name` |

### 5.3 音频处理

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `extract_audio` | 音频分离 | `video` → `audio` | `format`(wav/mp3/flac/m4a)、`sample_rate`(44100/48000/16000) |
| `vocal_separation` | 人声分离 | `audio` → `audio`(人声)/`background`(背景) | `method`(分离接口)、`model`、`format` |
| `track_separation` | 音轨分离 | `audio` → `vocals`/`bass`/`drums`/`guitar`/`piano`/`other` | `method`(demucs)、`model`(htdemucs_6s)、`format` |
| `merge_audio` | 音频合并 | `audio_manifest`/`video` → `audio`/`dub_srt`/`dub_bilingual_srt`/`video_adjusted` | `video_speed_adjust`、`speed_min/max`、`gap_threshold`、`audio_format` |

### 5.4 AI 处理链（ASR → 翻译 → 字幕）

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `asr` | 语音识别 (ASR) | `asr_audio`(必填)/`vocal_audio` → `subtitle`(ASR结果JSON) | `engine`、`language`(auto/zh/en/…)、`model`、`word_timestamps`、`hotwords` |
| `sentence_preprocess` | 断句预处理 | `json`/`text` → `subtitle`/`word_index` | `method`(asr/punct/ai)、`split_on_speaker` |
| `sentence_split` | 句子分割 | `subtitle`(ASR JSON) → `subtitle`/`text` | `max_sentence_length`、`use_llm_split`、`split_by_punct`、`merge_*`、`pause_split_threshold` |
| `summarize` | 内容总结 | `text` → `subtitle`(总结JSON) | `summary_length`、`use_custom_terminology`、`custom_terminology_file` |
| `translate` | 逐句翻译 | `subtitle`(必填)/`summary` → `subtitle`(直译)/`reflect`(反思) | `reflect_translate`(follow_global/yes/no)、`translation_style`、`batch_char_limit` |
| `subtitle_align` | 译文断句和双语对齐 | `subtitle` → `subtitle` | `max_subtitle_length` |
| `subtitle_gen` | 字幕生成 | `subtitle`(句子/翻译/对齐JSON) → `subtitle`(译文)/`original`(原文)/`bilingual`(双语) | `file_prefix`、`filter_punctuation` |
| `llm_request` | 通用LLM请求 | `text`/`image`/`json` → `result`(JSON)/`text` | `model`、`system_prompt`、`user_prompt`(可用 {input_text}/{input_json}/{source_language}/{target_language})、`temperature`、`response_json` |
| `editor_agent` | 剪辑AI Agent | `text`(编辑指令) → `project`/`artifacts`/`result` | `instruction`、`expert_role`(auto/general/design/audio/editing/storytelling) |

### 5.5 AI 生成类

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `dub_task` | 生成配音任务 | `subtitle`(句子时间戳JSON) → `text`(TTS任务单)/`pandas` | `ai_read_tone`、`normalize_chinese_read_text`、`ai_dialect_colloquial`、`dialect_name` |
| `tts` | 语音合成 (TTS) | `text`(任务单)/`pandas` → `text`/`pandas` | `tts_mode`(preset_voice/clone/controllable_clone/voice_design)、`tts_engine`、`clone_source`、`ref_audio_path`、`voice_role_1..4`、`speed_regenerate` |
| `cover` | AI封面设计 | `json`(内容JSON) → `prompt`(文本) | `design_mode`(ai_design/custom_prompt)、`custom_title`/`custom_subtitle`、`ai_prompt`、`custom_prompt` |
| `image_gen` | AI生图 | `text`/`image` → `images`(JSON列表)/`text`(首张图片) | `mode`(txt2img/img2img)、`interface`、`model`、`resolution`(1K/2K/4K)、`aspect_ratio`、`num_images`、`custom_prompt` |
| `aigc_comfyui` | ComfyUI 生图 | `text`/`reference_video`/`first_frame`/`image2..4`/`last_frame` → `images`/`first`/`files` | `workflow_json`(Z-Image 等)、`mode`(txt2img/img2img)、`resolution_*`（本地/局域网 ComfyUI，thread 域） |
| `aigc_runninghub` | RunningHub 生成 | 同上输入 → `images`/`first`/`files` | 云端 RunningHub 工作流（process 域，参数来自「其他能力接口」设置） |
| `aigc_jimeng` | 即梦 CLI 生成 | 同上输入 → `images`/`first`/`files` | 即梦 CLI（process 域） |

### 5.6 视频合成 / 发布

| 节点 id | 名称 | 输入 → 输出 | 关键 config |
|---|---|---|---|
| `merge_sub_video` | 字幕烧录 | `video`(必填)/`subtitle`(必填)/`audio`(BGM)/`dub`(配音) → `video` | `video_quality`(copy/high/medium/low)、`mute_original`、`bgm_volume`、`dub_volume`、`preset_id`(字幕样式) |
| `merge_dub_video` | 配音视频合成 | `video`/`audio`(配音) → `video` | 无 |
| `watermark` | 水印添加 | `video`/`image`(水印图) → `video` | `enabled`、`position`、`opacity` |
| `video_frame_extract` | 视频抽帧 | `video`/`srt`(字幕) → `image` | `video_source`(input_node/connection)、`time_point`、`time_mode`(positive/negative)、`avoid_subtitles` |
| `cutia` | Cutia 交互剪辑 | `video`/`audio`/`image`/`subtitle` → `video` | 无（手工剪辑，等待成片） |
| `video_publish` | 视频发布 | `video`(必填)/`cover_landscape`/`cover_portrait`/`json`(标题描述) → `text`/`result_file` | `account_ids`、`title`/`description`(留空读上游JSON)、`tags`、`publish_mode`(publish/platform_draft/local_draft)、`schedule_enabled`/`schedule_time`、`is_original` |

### 5.7 自定义节点

- 通过前端「节点管理器」创建或导入的节点自动出现在 `/api/node-types` 与节点面板中，id 即 `nodeType`。
- 定义存 `backend/config/node_types/{id}.json`，执行类型 `python`（内联代码或 `backend/nodes/{id}/run.py`）/ `shell` / `llm`。
- 编排时与内置节点一样按端口类型连线、填 config 即可。

## 6. 从用户需求编排工作流的步骤

### Step 1 识别输入
用户提供什么？→ 视频文件 / 音频文件 / 字幕文件 / URL / 纯文本。
→ 在 `input` 节点设置 `selectedTypes` 与对应 `videoPath`/`audioPath`/`subtitlePath`/`url`，并设置 `source_language`、`target_language`。

### Step 2 识别目标
用户想得到什么？
- **翻译配音成片**：input → extract_audio → asr → sentence_split → translate → subtitle_align → subtitle_gen → merge_sub_video；配音分支 → dub_task → tts → merge_audio → merge_dub_video
- **仅字幕**：input → extract_audio → asr → sentence_split → translate → subtitle_align → subtitle_gen
- **纯转写/提取文字**：input → extract_audio → asr → sentence_split（→ summarize）
- **封面图**：…json → cover → image_gen → image_preview / output
- **视频下载+处理**：input(url) → platform_download → …
- **发布**：… → video_publish
- **AI 封面/生图**：llm_request / cover → image_gen

### Step 3 连线（严格按端口）
- 上游输出端口 id → 下游输入端口 id，**类型必须相同**（见 4.2）。
- 例：`extract_audio` 输出 `audio` → `asr` 输入 `asr_audio`；`asr` 输出 `subtitle` → `sentence_split` 输入 `subtitle`。
- 例：`input` 输出 `video` → `extract_audio` 输入 `video`。

### Step 4 填 config
每个节点填关键配置（见第 5 节），**可省略的默认值不写**；语言、引擎、模型等留空则跟随全局配置。

### Step 5 保存与校验
- 保存到 `backend/config/workflows/{id}.json`（顶层 `type: "user"`）。
- 用前端「工作流编排」打开检查，或直接调用 API 验证：
  - `GET /api/workflows` 列表 / `GET /api/workflows/{id}` 详情
  - `POST /api/workflows/{id}/execute` 执行（body: `{nodes, edges, mode, task_id, input}`）

### Step 6 执行与断点
- 打开全局工作流时，前端自动调用 `POST /api/workflows/{id}/debug-task`（body 传画布快照）**接管固定调试任务**（`is_debug`，无则用画布快照初始化），后续调试执行都写回该任务、不每次新建。
- 执行模式 `mode`：
  - `debug` / `resume`：写回固定调试任务（或指定 `task_id` 任务），**增量重建**，保留已 succeeded 节点（断点续跑）。
  - `restart`：全量重建并重跑。
  - `restart_clean`：**从头执行**，先清空任务 `cache/` 再全量重建（对应前端「从头执行」）。
  - `new`：新建一个 **detached 一般任务** 并投递执行，与全局调试任务解耦。
- 「新建一般任务」编辑态：`POST /api/workflows/{id}/spawn-task`（仅建任务+写私有 `workflow.json`，不执行）。
- 一般任务「另存为全局」：`POST /api/workflows/{id}/save-as-global`。
- 节点级执行：`POST /api/workflows/{id}/execute-node`（`task_id` 必传且必须在当前任务边界内；`scope=node` 仅执行本节点——始终提交完整工作流、用 `exec_only` 收窄，不覆盖任务私有 workflow；`scope=downstream` 本节点及其连线下游）。
- 执行状态：`GET /api/workflows/{id}/status` 返回每个节点 `pending/running/completed/failed/skipped` 与产物。
- 历史任务打开「工作流编排」任务：任务 API 返回 `is_debug`，前端识别后以**全局工作流模式**加载画布（不显示为一般任务），执行仍写回同一调试任务。

> 详细的任务类型、产物清理语义与边界规则见《工作流运行指南》第 2、4 节。

## 7. 常见模板（可直接复制改写）

### 模板 A：本地视频 → 翻译配音成片（主链路）

```
input(video) → extract_audio → asr → sentence_split
                                          ├→ summarize → translate → subtitle_align → subtitle_gen → merge_sub_video → output
                                          └→ dub_task → tts → merge_audio → merge_dub_video ┘
```

节点示例（JSON 节选）：

```json
{
  "id": "n_001", "type": "workflow",
  "data": { "nodeType": "input", "label": "输入",
    "config": { "selectedTypes": ["video"], "videoPath": "D:/videos/source.mp4",
                "source_language": "auto", "target_language": "zh" } }
},
{
  "id": "n_002", "type": "workflow",
  "data": { "nodeType": "extract_audio", "label": "音频分离",
    "config": { "format": "wav", "sample_rate": "44100" } }
},
{
  "id": "n_003", "type": "workflow",
  "data": { "nodeType": "asr", "label": "语音识别", "config": { "language": "auto" } }
},
{
  "id": "n_004", "type": "workflow",
  "data": { "nodeType": "sentence_split", "label": "句子分割", "config": {} } }
```

```json
{ "id": "e_01", "source": "n_001", "target": "n_002",
  "sourceHandle": "out-video", "targetHandle": "in-video" },

  "sourceHandle": "out-audio", "targetHandle": "in-asr_audio" },
```

## 8. 常见错误与排查

| 错误现象 | 原因 | 修复 |
|---|---|---|
| 保存后边数变少 | 端口 id 或类型不匹配，被 `normalize_workflow` 删除 | 核对 `sourceHandle=out-<id>`、`targetHandle=in-<id>`、端口类型相同 |
| 执行报 `未知工作流节点: xxx` | `nodeType` 不在节点注册表 | 确认 id 拼写正确且已注册（见《节点新建规范指南》） |
| 节点一直 waiting 不执行 | 前置节点未完成或未连线 | 检查依赖边完整、上游 completed |
| 下游找不到产物 | 上游未产出该端口 / 端口 id 连错 | 核对上游 outputs 端口 id |
| input 节点没数据 | `selectedTypes` 未包含对应类型，或路径无效 | 检查 config：videoPath 需为本地绝对路径 |
| 中文乱码 / 进度不更新 | process 节点 stdout 编码或 WS 连接问题 | 重启后端+worker，确认 `/ws/tasks/{id}` 可连 |
| 执行节点报 `节点执行必须指定任务` | `execute-node` 未传 `task_id` | 节点执行必须在当前任务边界内，先打开/接管调试任务再执行（见《工作流运行指南》4.1） |
| 调试进度丢失、每次新建任务 | 全局工作流未走固定调试任务 | 打开工作流时前端会调用 `debug-task` 接管；确认前端已更新 |

## 9. 编排红线（必读）

1. **一个工作流只用一个 `input` 节点作为数据源**（需要多路输入可复用其 var1/var2 或再放 input）。
2. **节点 id 画布内唯一**，`data.nodeType` 必须是第 5 节清单中的 id。
3. **连线端口类型必须一致**，`any` 万能；同一输入端口只连一条边。
4. **config 的 key 必须来自该节点 `configFields`**，未知 key 会被忽略（不报错但无效）。
5. **不要手写 `type: "task"` 的工作流**，那是执行快照。
6. 大工作流建议分段编排，先用 `sentence_split`/`preview` 节点验证中间产物，再补全下游。
7. **不要手写 `control_plane_workspaces/{task_id}/workflow.json`**：任务私有快照由执行/保存自动维护，与全局工作流文件解耦。
8. **节点执行（execute-node）必须在任务边界内**：必须携带 `task_id`（固定调试任务或当前一般任务），后端会拒绝空/跨任务的节点执行。
