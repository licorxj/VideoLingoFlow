# 接口添加指南（面向智能体）

> 本文档指导智能体在 VideoLingoFlow 中**添加与管理各种「能力接口」**：ASR 语音识别、TTS 语音合成、AI 生图、人声分离，以及 AIGC 能力（ComfyUI/RunningHub/即梦）。
> 覆盖两种场景：① 给设置页**新增一个接口实例**（运行态配置）；② 给系统**新增一种接口域/能力**（开发态，仿照现有四域）。
> 所有约定均以当前代码库真实实现为准。

---

## 1. 接口体系总览

「接口」= 设置页里可配置、可开关、可测试的后端能力提供方（引擎/服务商）。系统现有四类接口域 + 一类 AIGC 能力：

| 接口域 | 数据文件 | Manager | API 路由 | 前端设置组件 |
|---|---|---|---|---|
| ASR 语音识别 | `backend/config/asr_interfaces.json` | `backend/asr/asr_interface_manager.py` | `/api/asr-interfaces` | `ASRInterfaceEditor.tsx` |
| TTS 语音合成 | `backend/config/tts_interfaces.json`（+ `tts_voices.json` 音色） | `backend/tts/tts_interface_manager.py` | `/api/tts-interfaces`、`/api/tts-voices` | `TTSInterfaceEditor.tsx` |
| AI 生图 | `backend/config/imagegen_interfaces.json` | `backend/imagegen/imagegen_interface_manager.py` | `/api/imagegen-interfaces` | `ImageGenInterfaceEditor.tsx` |
| 人声分离 | `backend/config/separation_interfaces.json` | `backend/separation/separation_interface_manager.py` | `/api/separation-interfaces` | `SeparationInterfaceEditor.tsx` |
| AIGC 能力 | `backend/config/config.yaml`（`aigc.*`） | `backend/api/aigc_capabilities.py` 直接读写 | `/api/aigc` | `AigcCapabilitiesSettings.tsx` |

**四类接口域完全同构**，都遵循：JSON 数据文件 → Manager（单例、线程锁、CRUD）→ REST API（CRUD + toggle + reload + test）→ 前端编辑器 → 节点消费（configFields `api-select` + 步骤内合并参数）。

## 2. 接口数据模型

### 2.1 文件结构

`{domain}_interfaces.json`：

```json
{
  "version": 1,
  "interfaces": [
    {
      "id": "mimo_asr",
      "name": "MiMo ASR",
      "type": "local",
      "builtin": true,
      "enabled": true,
      "description": "…",
      "config": { "...": "见 2.3" }
    }
  ]
}
```

### 2.2 顶层字段约定

| 字段 | 说明 |
|---|---|
| `id` | 唯一接口 id。自定义接口不传则由 Manager 生成 `uuid4().hex[:8]`；**节点 config 的 `engine`/`interface` 用它引用** |
| `name` | 显示名（引擎下拉选项 label） |
| `type` | 调用方式：`local`/`sdk`（ASR、分离）；`local`/`sdk`/`online`（TTS）；`sdk`/`openai_compatible`（生图）。**不同域 type 取值不同，见第 4 节** |
| `builtin` | 内置接口：**不可删除**、不可改 name/type/enabled，只可改 `description`/`config`；自定义接口全字段可改 |
| `enabled` | 开关；`get_enabled()` 只返回启用项 |
| `description` | 说明 |
| `config` | 接口参数（见 2.3） |

### 2.3 config 通用字段

**所有域通用**：

| 字段 | 说明 |
|---|---|
| `api_url` / `api_key` / `endpoint` / `timeout` | local 型 HTTP 调用（api_key → `Authorization: Bearer`） |
| `body_type` | `form`（multipart）或 `json` |
| `custom_params` | `[{key, default, description}]`，请求时自动带上默认值 |
| `model_options` / `voice_options` | 模型/音色下拉选项（节点 api-select 数据源） |
| `model_list_url` / `model_list_key` / `voice_list_url` / `voice_list_key` | 从远程接口拉取模型/音色列表的配置 |
| `sdk_package` / `sdk_module` / `sdk_function` / `sdk_api_key` / `sdk_extra_args` | sdk 型动态 import 调用 |
| `max_concurrent` / `timeout` | 并发与超时 |
| `modes` | 能力子模式开关（TTS：clone/preset_voice/voice_design/controllable_clone；生图：txt2img/img2img），每个 `{enabled, endpoint}` |

> `config` 字段**自由扩展**：Manager 只做存取，不做白名单校验；步骤侧用 `cfg.get(key)` 读取。新增配置项只需在 Manager `_default_config` 与前端编辑器补上。

## 3. 四件套（添加新接口的完整链路）

新增任何接口（实例或新域）都需要让这四个环节打通：

```
① 数据文件 → ② Manager（CRUD + 参数组装） → ③ REST API（暴露给前端）
                                                └→ ④ 节点消费（configFields api-select + 步骤合并参数）
```

- **① 数据文件**：`backend/config/{domain}_interfaces.json`，`utf-8-sig` 编码。
- **② Manager**：`backend/{domain}/{domain}_interface_manager.py`，必须提供：
  - `_load/_save`（JSON 读写）、`reload`、`list_all`、`get(id)`、`get_enabled`、`get_engine_ids`
  - `create/update/delete/toggle`（`builtin` 保护）
  - `_default_config(type)`（每种 type 一套默认 config）
  - `build_request_params(...)` / `_build_sdk_params` / `_build_http_params`（参数组装，供测试与节点复用）
  - 模块级单例工厂：`get_xxx_interface_manager()`（`_manager = None` 惰性初始化）
- **③ REST API**：`backend/api/{domain}_interfaces.py`，标准端点集：
  - `GET ""`（列表）、`GET "/enabled"`、`GET "/{id}"`、`GET "/models"`（按引擎分组的模型下拉）、`GET "/config-fields"`（节点引擎下拉动态数据，ASR 有）
  - `POST ""`（创建）、`PUT "/{id}"`（更新，`exclude_none=True`）、`DELETE "/{id}"`（builtin 拒绝）、`POST "/{id}/toggle"`、`POST "/reload"`
  - `POST "/{id}/test"`（连通性测试，异步线程池执行）、`POST "/upload-*"`（测试素材上传）、`GET "/test/result/{file}"`、`DELETE "/test/cleanup"`
  - 域专属：TTS `/api/tts-voices`（音色 CRUD）、生图 `/models`、`/models-for-node`、`/params/{model}`、`/refresh-balance`、`/fetch-models`
  - **在 `backend/main.py` 注册路由**（`app.include_router(...)`），并在 `backend/api/__init__.py` 同步 import。
- **④ 节点消费**：节点 `configFields` 用 `api-select` + `apiEndpoint` 动态拉引擎/模型；步骤类运行时用 Manager 取配置合并参数（见第 6 节）。

## 4. 各域差异速查

### 4.1 ASR（`/api/asr-interfaces`）

- `type`：`local`（HTTP）| `sdk`（Python 动态导入）。
- config 专属：`language_param`、`audio_param`（form 文件字段名）、`endpoint`（默认 `/v1/audio/transcriptions`）、`word_timestamps`、`diarize`、`hotwords`、`sdk_language_list_function`、`model_list_url/key`。
- 节点接入：`asr` 节点 configFields——`engine` 用 `api-select` 拉 `/api/asr-interfaces/enabled`，`model` 拉 `/api/asr-interfaces/models`，`compute_type` 拉 `/api/asr-interfaces/config-fields`。
- 步骤消费：`s02_asr.py` 的 `_resolve_engine_id`（任务 config `engine` > 默认）→ `_load_default_interface_config(engine_id)` 读接口默认 config → `_merge_asr_params` 合并 → `get_asr_engine` 执行。
- 测试：`POST /{id}/test`（需先 `upload-audio` 拿音频路径）。

### 4.2 TTS（`/api/tts-interfaces` + `/api/tts-voices`）

- `type`：`local` | `sdk` | `online`（OpenAI 兼容在线）。
- config 专属：`text_param`、`speed_param`、`ref_audio_param`、`voice_design_param`、`controllable_clone_param`、`modes`（clone/preset_voice/voice_design/controllable_clone 四模式开关+endpoint）、`api_source_url`。
- **音色**：单独文件 `tts_voices.json`（`{"version":1,"voices":{...}}`），`/api/tts-voices` 管理；音色与接口通过 `voice_router` 关联。
- 节点接入：`tts` 节点 configFields——`tts_engine` 用 `api-select` 拉 `/api/tts-interfaces/enabled`，`tts_mode`、`voice_role_*` 等。

### 4.3 AI 生图（`/api/imagegen-interfaces`）

- `type`：`sdk` | `openai_compatible`。
- config 专属：`default_model`、`model_metadata`（模型参数表）、`balance_endpoint`（余额查询）、`modes`（txt2img/img2img）。
- 专属端点：`GET /{id}/models`、`GET /{id}/models-for-node?mode=txt2img|img2img`（节点模型下拉）、`GET /{id}/params/{model}`、`POST /{id}/refresh-balance`、`POST /{id}/fetch-models`、`DELETE /{id}/models/{model_name}`。
- 节点接入：`image_gen` 节点 configFields——`interface` 用 `api-select`，`model` 按 interface+mode 动态拉取。

### 4.4 人声分离（`/api/separation-interfaces`）

- `type`：`local` | `sdk`。
- config 专属：`audio_param`、`endpoint`（默认 `/v1/separate`）、`format`、`sdk_class`（SDK 类名，区别于 function）。
- 节点接入：`vocal_separation`/`track_separation` 节点 `method` 引擎下拉。

### 4.5 AIGC 能力（`/api/aigc`，与四域不同）

- 不是接口实例，而是三个固定能力块：`comfyui` / `runninghub` / `jimeng`，配置存 `config.yaml` 的 `aigc.*`。
- 端点：`GET/PUT /config`、`GET /status`、`POST /comfyui/test`、`POST /runninghub/test`、`POST /jimeng/version`。
- 对应节点：`aigc_comfyui`（thread）、`aigc_runninghub`/`aigc_jimeng`（process）。

## 5. 场景一：新增一个接口实例（运行态，最常见）

用户要在设置页加一个 ASR/TTS/生图/分离接口时，**优先走前端设置页**（自动落盘 + 即时测试）；智能体也可直接调 API 或写 JSON。推荐步骤：

1. 确定接口域与 `type`（HTTP 还是 SDK）——先看目标服务提供什么。
2. 收集必要字段：`api_url`+`endpoint`+`api_key`（local）、或 `sdk_package/module/function`（sdk）、模型/音色列表（`model_options`/`voice_options`）、请求体字段名（`audio_param`/`language_param`/`text_param` 等）。
3. **写默认 config 模板**：在对应 Manager 的 `_default_config` 中补充新 type 的默认字段（如需新 type），并更新前端编辑器 `EMPTY_*` 常量（保持两边一致）。
4. 写入数据文件（或走 API）：
   - API：`POST /api/{domain}-interfaces`，body `{name, type, enabled, description, config}`；`builtin` 不传（自动 False）。
   - 或直接编辑 `{domain}_interfaces.json`（`builtin:false`）。
5. **测试**：调 `POST /api/{domain}-interfaces/{id}/test`（ASR 先 upload-audio）验证连通。
6. **在节点里可用**：节点引擎下拉会自动出现（`/enabled` / `config-fields`）；不出现先 `POST /reload`。
7. 交付检查：`GET /api/{domain}-interfaces` 能看到；`enabled=true`；测试通过；节点下拉可选。

> 红线：**不要**手改 `builtin:true` 的内置接口去新增引擎——内置接口用于系统自带引擎，新服务一律建自定义接口。

## 6. 场景二：新增一种接口域（开发态）

给系统增加一个全新的能力域（例如「视频增强接口」），完全仿照现有四域：

- [ ] **① 数据文件**：`backend/config/xxx_interfaces.json`（`{"version":1,"interfaces":[]}`）
- [ ] **② Manager**：`backend/xxx/xxx_interface_manager.py`——实现第 3 节列出的全部方法 + 单例工厂 `get_xxx_interface_manager()`
- [ ] **③ API**：`backend/api/xxx_interfaces.py`——标准端点集（列表/CRUD/toggle/reload/test/upload/cleanup）+ 域专属端点；在 `backend/main.py` 与 `backend/api/__init__.py` 注册
- [ ] **④ 前端**：`frontend/src/api/xxxInterfaces.ts`（类型+请求）、`components/settings/XxxInterfaceEditor.tsx`（编辑器）、在设置页挂载入口
- [ ] **⑤ 节点接入**：
  - `builtin_node_types.py` 新增节点，configFields 用 `api-select` + `apiEndpoint` 指向 `/api/xxx-interfaces/enabled`
  - 步骤类（`backend/steps/s_xxx.py`）内 `get_xxx_interface_manager().get(engine_id)` 读取接口 config，合并参数执行
- [ ] **⑥ 验证**：建接口 → 测试 → 节点下拉可选 → 工作流执行产物正确

---

## 7. 节点如何消费接口（重要）

1. **前端下拉**：节点 configFields 的 `api-select` 字段配置 `apiEndpoint`（如 `"/api/asr-interfaces/enabled"`），前端据此拉引擎列表；`dependsOn` 实现联动（选引擎后拉模型）。
2. **步骤合并参数**：节点 `config.engine`（或 `interface`/`method`）存的是接口 `id`；步骤内用 Manager 取接口 config 作为默认值，任务节点 config 覆盖默认值：
   - ASR：`s02_asr.py` `_resolve_engine_id` → `_load_default_interface_config` → `_merge_asr_params`
   - 通用原则：`merged = {**interface_config, **node_config}`，`engine` 本身不传给引擎（仅路由用）。
3. **不要在步骤里硬编码引擎**：新引擎一律通过接口配置注入，避免代码里堆 `if engine == "xxx"`。

## 8. 测试与验证

| 检查项 | 方式 |
|---|---|
| 接口列表/启用 | `GET /api/{domain}-interfaces`、`GET /api/{domain}-interfaces/enabled` |
| 连通性 | `POST /api/{domain}-interfaces/{id}/test`（ASR/TTS 需先上传素材） |
| 节点下拉 | 打开节点配置，确认引擎/模型下拉出现该接口 |
| 端到端 | 工作流中放置对应节点并执行，产物正确、进度正常 |
| 持久化 | 重启后端后接口仍在（JSON 落盘） |
| 内置保护 | 对 `builtin:true` 接口 DELETE 应返回 400 |

## 9. 常见错误与排查

| 错误现象 | 原因 | 修复 |
|---|---|---|
| 节点引擎下拉没有新接口 | Manager 未 reload / 接口 `enabled=false` | `POST /{domain}-interfaces/reload`；确认 enabled |
| 测试 401/403 | `api_key` 为空或格式不符 | 填对 key；local 请求头固定 `Authorization: Bearer` |
| form 上传失败 | `audio_param`/`body_type` 与目标服务不符 | 核对目标服务字段名与 content-type |
| sdk 调用报 `Function not found` | `sdk_function` 拼写或模块路径错 | 用 `sdk_module` 精确指向；确认函数可导入 |
| 删除接口失败 400 | 接口是 builtin | 内置接口不可删，只可改 description/config |
| 步骤执行仍用旧引擎 | 节点 config 里 `engine` 已写死 | 清空节点 engine（跟随全局/接口默认） |
