# 项目架构（面向智能体）

> 本文档帮助**智能体/开发者快速理解 VideoLingoFlow 的系统如何运转**：分层、数据流、任务生命周期、执行隔离、通信方式、部署形态与关键代码路径。
> 配套文档：[项目目录功能说明.md](项目目录功能说明.md)（逐目录定位）、[工作流编排指南.md](工作流编排指南.md)、[节点新建规范指南.md](节点新建规范指南.md)。

## 1. 系统全景

VideoLingoFlow 是**本地优先的一站式 AI 视频创作与本地化平台**，按功能分四层：

```text
┌────────────────────────── 前端（React + Vite） ──────────────────────────┐
│ 工作流编排 / 批量工作台 / 历史项目 / 多人协作 / 共享社区 / 小Pi / 配音谷 / 剪辑 / 发布 / 设置 │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ REST + WebSocket 事件流（/ws/tasks/{id}）+ SSE（Pi 事件）
┌───────────────▼─────────────────────────────────────────────────────────┐
│                    后端（FastAPI，backend/main.py）                       │
│  backend/api/*      → 全部 REST/WS 路由（tasks/workflows/batch/control/…）│
│  backend/control_plane/* → 控制平面：DB、任务运行时、Celery 封装、安全      │
│  backend/engine/*    → 批量执行器、步骤流水线、任务管理                     │
│  backend/steps/*     → 40+ 节点步骤（s_*.py，继承 BaseStep）              │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ Celery 投递（Redis broker）
┌───────────────▼─────────────────────────────────────────────────────────┐
│        Celery Worker（--pool=threads --concurrency=4）                   │
│  thread 域：线程内执行步骤；process 域：python -m step_worker 子进程隔离     │
└──────────────────────────────────────────────────────────────────────────┘
```

**核心思想**：一切生产活动都是「任务」（Task）；任务由「工作流（节点 + 连线）」定义；节点是实际执行单元；控制平面负责任务的创建、调度、状态机、产物清理与资源限流。

## 2. 控制平面（Control Plane）

### 2.1 组成

| 组件 | 位置 | 职责 |
|---|---|---|
| FastAPI 应用 | `backend/main.py` | 挂载全部路由与中间件（CORS / RemoteAccessGuard / Correlation） |
| 数据模型 | `backend/control_plane/models.py` | `Task`、`TaskNode`、`User`、`Project`、`WorkflowVersion`、`Asset`、`AuditEvent` 等（表前缀 `cp_`） |
| 数据库 | `data/control-plane.db`（SQLite，WAL） | 任务、用户、项目、审计等（Docker 部署用 PostgreSQL） |
| 运行时 | `backend/control_plane/workflow_runtime.py` | 任务提交、状态机、节点执行、组合展开、产物清理、rich 日志 |
| 状态机 | `backend/control_plane/runtime.py` | `TASK_TRANSITIONS` / `NODE_TRANSITIONS`、资源令牌、错误分类 |
| Celery | `backend/control_plane/celery_runtime.py` | broker 连接与 `send_task("videolingo.workflow.execute")` |
| 安全 | `backend/control_plane/security.py` | 用户/角色/项目权限（多人协作的权限底座） |

### 2.2 任务（Task）与节点（TaskNode）

- `Task`：一个可执行单元。`payload` 存 `workflow`（工作流字典）、`input`（输入配置）、`mode`、`resume_from`、`exec_only`、`is_debug`/`detached`/`batch` 等身份标记。
- `TaskNode`：任务内的节点，`payload` 存节点定义与执行结果（`result.outputs` 端口映射、`message`、`progress`）。
- 状态机（任务级）：`created → queued → running → succeeded/failed/cancelled/deleted`，`paused/stopping/deleting` 为中间态。

### 2.3 任务工作区（Workspace）

每个任务一个目录 `control_plane_workspaces/{task_id}/`：

```
{task_id}/
├── cache/          # 中间产物（asr 结果、翻译 json、任务单…）
├── output/         # 最终产物（合成视频、音频、字幕文件…）
├── workflow.json   # 任务私有工作流快照（与全局解耦）
└── task.json       # 旧前端兼容的任务状态镜像（节点状态/产物）
```

> 产物/输入多为**相对 task_dir 的相对路径**；步骤读取时必须 `os.path.isabs` 判断后拼接（见《节点新建规范指南》§7）。

## 3. 任务生命周期（关键链路）

以「前端在画布点击执行」为例：

1. **定位任务**：`POST /api/workflows/{wf_id}/execute`（mode=debug）→ `_find_debug_task` 定位固定调试任务（无则 `debug_init` 创建）；mode=new 则新建 detached 一般任务。
2. **提交**：`submit_workflow(workflow, input, mode, task_id, exec_only)` → `normalize_workflow` 校验/补全（节点缺 `position` 自动补网格坐标）→ 落库（`_merge_task_payload` 保留 `is_debug`/`detached`/`batch` 身份）→ 重建 `TaskNode` 行 → 置 `queued` → Celery `send_task` 投递到 IO 队列。
3. **执行**：Worker 调 `execute_workflow(task_id)` → `running` → `_prepare_workspace` 落盘 → 拓扑排序 + `exec_set`（`resume_from` 截断 ∩ `exec_only`）→ 逐节点 `_run_node`。
4. **节点执行**：`_run_node` 按 `execution_domain` 分派——thread 域线程内直接跑步骤；process 域起子进程 `python -m backend.control_plane.step_worker`（可记录 PID 硬停止）。结果写回 `TaskNode.payload.result.outputs` + `task.json`。
5. **收尾**：全部节点完成 → 任务 `succeeded`（被请求删除则 `deleted` 并删文件夹）→ 前端经 WebSocket 收到状态事件实时刷新。

### 3.1 单飞保护

非终态（非 paused）任务重复提交直接返回，避免重复投递；`request_cancel`/`request_delete` 可中断（`deleting` → worker 或 API 侧收尾为 `deleted` 并删除任务文件夹）。

### 3.2 产物清理语义

- 端点「从头执行」`restart_clean`：清空 `cache/`。
- 节点执行 `scope=node`：仅清该节点产物（`_clear_nodes_artifacts([node_id])`）；`scope=downstream`：清节点及其连线下游。
- 删除任务/工作流：级联 `request_delete`（DB 置 deleted + 删 `control_plane_workspaces/{task_id}` 文件夹）。

## 4. 执行域与隔离（方案 C）

| 域 | 判定 | 行为 | 适用 |
|---|---|---|---|
| `thread` | 节点定义 `execution_domain: "thread"`（默认） | 线程内直接执行，靠协作取消（callback 检查取消标记） | 轻量计算、文件转换 |
| `process` | `execution_domain: "process"` | 子进程 `step_worker` 执行，可记录 PID 并 `taskkill` 硬停止；结果 pickle 回传，进度走 `@PROGRESS@|pct|msg` stdout 协议 | ASR/TTS/翻译/生图/下载/发布等重型或网络节点 |

> Celery 以 `--pool=threads` 运行；进程域节点真正跨进程隔离，避免重型推理拖垮主进程。

## 5. 数据与存储

| 数据 | 位置 | 说明 |
|---|---|---|
| 控制平面 DB | `data/control-plane.db` | 任务/用户/项目/审计（表前缀 `cp_`），WAL 模式 |
| 配音谷 DB | VoiceForge 独立数据库（`backend/voiceforge/database.py`） | 配音项目/角色/资产/音色 |
| 全局工作流 | `backend/config/workflows/{wf_id}.json` | `type:"user"`，前端保存 |
| 自定义节点 | `backend/config/node_types/{node_id}.json` + `backend/nodes/{id}/` | 节点管理器创建/导入；静态步骤未命中时由 `custom_node_runtime.py` 运行 |
| 已删除内置节点 | `backend/config/deleted_builtin_node_ids.json` | 内置定义的持久化隐藏记录；引用该 id 的工作流会被拒绝 |
| 任务工作区 | `control_plane_workspaces/{task_id}/` | cache/output/workflow.json/task.json |
| 共享社区 | 云端 Cloudflare R2 + D1 | 节点/工作流资源包 |
| 配置 | `backend/config/config.yaml` + `.runtime/local_env.bat` 覆盖 | 接口、模型、Pi、批量参数等 |

## 7. 三大协作功能（新增模块）

### 7.1 多人协作（Control Plane 权限体系）

- 表：`cp_users / cp_roles / cp_user_roles / cp_sessions / cp_projects / cp_project_members / cp_workflow_versions / cp_assets / cp_audit_events / cp_join_applications`。
- 能力：注册申请/审批、角色（admin/editor/viewer）、项目 ACL、资源中心（素材/产物上传下载）、工作流版本协同（revision 冲突检测）、审计日志。
- 访问控制：局域网（LAN Mode）监听 0.0.0.0；远程（Remote Mode + Cloudflare Tunnel）默认关闭，由 `RemoteAccessGuard` 拦截公网请求，控制面开关实时生效。
- 代码：`backend/api/control_plane.py`、`control_plane_assets.py`、`control_plane_workspace.py`、`collaboration_ws.py`、`backend/control_plane/security.py`；前端 `pages/Collaboration.tsx`。

### 7.2 共享社区（Cloudflare Worker + R2 + D1）

- 能力：把自定义**节点**（node_config + code + 预览图）与**工作流**打包成资源包，发布到云端社区；或从社区导入/安装。
- 代码：`backend/api/community.py`（pack-node / pack-workflow / publish / analyze-workflow-package / import-workflow / packages）、`cloudflare/src/index.js`（Worker，负责 R2 存储 + D1 元数据 + 治理删除）、`frontend/pages/Community.tsx`。
- 安全：发布公开但有限频限大小；治理删除令牌只存 Cloudflare Secret。

### 7.3 小 Pi（项目专用智能体）

- 能力：内嵌工作台侧边栏，六种角色（通用/节点创建/工作流编排/任务执行/文件整理/作品发布），流式对话、会话历史、工具调用。
- 代码：`backend/api/pi_rpc.py`（/api/pi/*）、`backend/pi_rpc/`（session 管理 + RPC client，驱动 `thirdparty/pi` 的 coding-agent CLI）、`frontend/components/agent/PiAssistantWindow.tsx`、设置页 `AgentSettings.tsx`。
- 配置：`config.yaml` 的 `pi.*`（enabled/model/node_path/cli_path）。

### 7.4 GPU 服务（可选）

- `backend/gpu_service/` 是独立于 Celery 的本地 GPU lane 调度层，通过 Redis 队列按需启动 lane、监测显存并在空闲后释放显存。
- 当前仅接管 ASR 和人声/音轨分离；服务不可用时相关节点会回退到原有进程内执行。
- Manager 仅在 `GPU_SERVICE_ENABLED` 为真时启动该服务。显存余量、并发 lane、空闲超时等由 `.runtime/local_env.bat` 的 `GPU_SERVICE_*` 配置控制。

## 9. 关键代码路径速查

| 场景 | 入口 → 关键函数 |
|---|---|
| 打开工作流接管调试任务 | 前端 `loadWorkflow` → `POST /api/workflows/{id}/debug-task` → `submit_workflow(mode="debug_init")` |
| 执行整个工作流 | `POST /api/workflows/{id}/execute` → `submit_workflow(mode=debug/new/…)` → Worker `execute_workflow` → `_run_node` |
| 执行单个节点 | `POST /api/workflows/{id}/execute-node`（task_id 必传）→ `submit_workflow(mode="resume", exec_only=[node])` |
| 节点重跑清产物 | `_clear_nodes_artifacts(task_id, clear_ids, workspace)` → `BaseStep.clear_artifact` |
| 删除任务/工作流 | `request_delete(task_id)` → 状态机 + `shutil.rmtree(workspace)` |
| 批量投递 | `BatchExecutor._deliver_loop`（限流 + 间隔）→ `_enqueue(task_id, mode)` |
| 多人协作鉴权 | `security.current_user` / `project_access` / `require_permission` |
| 社区打包发布 | `community.py: pack-node → publish → Worker /api/resources` |

## 10. 给智能体的三条铁律

1. **改执行逻辑先看本文件第 3 节与 `backend/control_plane/workflow_runtime.py`**：任务隔离、执行模式、产物清理、节点边界是高频出错点。
2. **新建节点看《节点新建规范指南》**：源码内置节点需要 builtin_node_types + 步骤类 + step_registry；节点管理器自定义节点走运行时定义，产物文件名必须带节点 id 后缀。
3. **编排工作流看《工作流编排指南》**：端口类型连线必须一致，`position` 必填（后端 normalize 会自动补齐）。
