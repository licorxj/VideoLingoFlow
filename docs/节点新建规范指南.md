# 节点新建规范指南

> 本文档指导智能体在 VideoLingoFlow 中正确、规范地**新建节点、注册节点、存放节点文件**。
> 所有约定均以当前代码库的真实实现为准（控制平面 + Celery 架构，方案 C 子进程隔离）。

---

## 1. 节点体系总览

本节描述的是**源码内置节点**的开发规范。源码内置节点由 **4 个部分**组成，缺一不可：

| 部分 | 文件位置 | 作用 | 是否必须 |
|---|---|---|---|
| ① 节点类型定义 | `backend/config/builtin_node_types.py` | 节点元数据（id/名称/端口/配置项/执行域） | 必须 |
| ② 步骤执行类 | `backend/steps/s_*.py` | 实际执行逻辑（继承 `BaseStep`） | 必须 |
| ③ 步骤注册 | `backend/steps/step_registry.py` | 节点类型 id → 步骤实例的映射 | 必须 |
| ④ 前端节点定义 | `frontend/src/lib/fallbackNodeTypes.ts` | 前端渲染兜底注册表（后端 API 不可用时的副本） | 建议同步 |

> 前端正常运行时会通过 `GET /api/node-types` 从后端拉取节点类型（`NodePalette.tsx` → `listNodeTypes()`），所以 ①②③ 是硬性要求；④ 是后端暂不可用时的兜底副本，建议同步保持一致。

### 1.1 节点管理器自定义节点

不需要修改项目源码时，优先使用节点管理器创建自定义节点。它只保存 `backend/config/node_types/{id}.json`，不进入 `builtin_node_types.py`、`backend/steps/` 或 `step_registry.py`。

- 可配置图标、端口 ID/类型、必需输入、配置字段与 `defaultConfig`。
- `execType` 支持 `python`、`shell`、`llm` 或空值（输入透传）。Python 必须填写内联代码或已有入口文件；Shell/LLM 必须填写执行内容。
- 自定义节点由控制面 `custom_node_runtime.py` 运行，`execTimeout` 为秒；内联 Python 通过 `produced` 字典返回端口输出。
- 导入节点包时，内置节点 ID 不可覆盖；包内入口文件必须存在。当前不会自动安装包内 `requirements.txt`，依赖应由部署环境预先提供。
- 保存组合时会生成 `kind: "group"` 的自定义节点，保存的是子图定义，执行时自动展开，不使用 Python/Shell/LLM 执行器。

## 2. 步骤文件存放规范（backend/steps/）

### 2.1 文件命名

- 步骤文件统一放在 **`backend/steps/`** 目录（一个目录，不分子目录）。
- 文件命名：`s_<节点类型id>.py` 或沿用现有编号风格 `sNN_<名称>.py`。
  - 新节点推荐：`s_<节点类型id>.py`（如 `s_my_node.py`）
  - 既有编号文件可继续沿用（如 `s15_extract_audio.py`），不要重复新建同名文件。
- 文件顶部写一行模块说明：`"""s_xxx: <一句话描述>"""`。

### 2.2 类命名与继承

- 类名以 `S_` 或 `Step` 开头，语义化命名，如 `S_MyNode` / `StepMyNode`。
- **必须继承 `backend.steps.base_step.BaseStep`**。
- 类内至少声明 `step_id` 和 `step_name`；`dependencies` 留空列表。

### 2.3 必须实现的方法（BaseStep 抽象方法）

| 方法 | 职责 | 说明 |
|---|---|---|
| `check_artifact(task_dir) -> bool` | 检查本节点产物是否已存在且有效 | 用 `find_artifact` 匹配产物；产物存在则跳过执行 |
| `validate_inputs(task_dir) -> bool` | 检查必需输入是否存在 | 优先读 `self._step_inputs`（连线输入），回退扫描缓存 |
| `run(task_dir, callback=None) -> dict` | 执行节点逻辑 | 返回 `{"artifacts": [...], "outputs": {...}}` |

### 2.4 run 的返回结构（重要）

```python
def run(self, task_dir, callback=None) -> dict:
    return {
        "artifacts": ["cache/my_result_abc123.json"],   # 产物相对路径（相对 task_dir）
        "outputs": {"json": "cache/my_result_abc123.json"},  # 端口 id -> 产物路径
    }
```

- `outputs` 的 **key 必须与 builtin_node_types 里本节点的 outputs 端口 id 一一对应**，下游连线按端口 id 取。
- `artifacts` 用于产物检测/清理，可包含 outputs 之外的辅助文件。

### 2.5 进度上报与取消（方案 C 规范）

`run` 内通过 `callback(percent: int, message: str)` 上报进度（0-100）：
```python
if callback:
    callback(10, "开始处理...")
    callback(100, "完成")
```

- **子进程隔离节点（execution_domain="process"）**：callback 会把进度以 `@PROGRESS@|pct|msg` 行协议写到 stdout 由父线程解析；协作取消通过检查取消标记文件实现（见 5.3）。
- **线程内节点（execution_domain="thread"）**：callback 直接同步回调。
- 在耗时循环中尽量定期调用 callback；阻塞型节点由父进程 kill 兜底。

## 3. 节点类型定义规范（backend/config/builtin_node_types.py）

在 `BUILTIN_NODE_TYPES` 列表末尾追加一个 dict，字段如下：

```python
{
    "id": "my_node",            # 唯一节点类型 id（前端 palette、连线、step_registry 都用它）
    "name": "我的节点",          # 显示名称
    "execution_domain": "thread",  # "process"（子进程隔离）或 "thread"（线程内，默认）
    "category": "process",      # 分类：input/process/ai/ai_gen/utility/output/preview/publish/flow_control
    "description": "一句话描述",
    "icon": "Wrench",           # lucide-react 图标名
    "color": "#6366f1",         # 主题色
    "inputs": [
        {"id": "json", "label": "JSON输入", "type": "json", "required": True},
        # type 可选：video/audio/audio_manifest/json/pandas/subtitle/text/image/url/any
    ],
    "outputs": [
        {"id": "json", "label": "结果", "type": "json"},
    ],
    "defaultConfig": {"key": "默认值"},   # 节点默认配置
    "configFields": [                     # 前端表单字段定义
        {"key": "key", "label": "配置项", "type": "text"},
    ],
}
```

### 3.1 execution_domain 判定标准（关键）

| 值 | 适用场景 | 说明 |
|---|---|---|
| `"process"` | 本地重型推理（ASR/TTS/生图/人声分离等）、网络请求类（下载/发布/LLM） | 独立子进程运行，可硬停止（taskkill），需要 `step_worker` 协议（见 5） |
| `"thread"` | 轻量、纯 CPU 计算、文件转换、几乎瞬时完成 | 线程内直接执行，无法硬杀，靠协作取消 |

当前 process 节点：`platform_download`、`vocal_separation`、`track_separation`、`asr`、`summarize`、`translate`、`tts`、`llm_request`、`image_gen`、`editor_agent`、`video_publish`、`aigc_runninghub`（RunningHub 生图）、`aigc_jimeng`（即梦 CLI 生图）。`aigc_comfyui`（ComfyUI 生图）为 thread 域。

### 3.2 端口 type 必须与前端 PortType 对齐

前端 `frontend/src/lib/workflowTypes.ts` 的 `PortType`：`video | audio | audio_manifest | json | pandas | subtitle | text | image | url | any | preview`。连线规则：`canConnect` 要求端口 type 相同（`any` 可连任何）。

### 3.3 configFields 常用字段类型

`text | textarea | select | checkbox | toggle | chips | file | hotwords | language-select | api-select | voice-select | slider | number | datetime-local | account-select | audio-selector | date | time`。

常用辅助字段：`placeholder`、`description`、`dependsOn`（联动）、`dependsValue`/`dependsAnyValues`、`fileFilter`（文件选择过滤）、`options`（select/chips 选项）、`colSpan`（"half"/"third"/"full" 布局）。

## 4. 步骤注册规范（backend/steps/step_registry.py）

`step_registry.py` 的 `_STEPS` dict 把 **节点类型 id** 映射到 **步骤实例**：

```python
from backend.steps.s_my_node import S_MyNode

_STEPS = {
    # ...既有注册...
    "my_node": S_MyNode(),      # 节点类型 id -> 实例（get_step_instance 用它解析）
    "s_my_node": S_MyNode(),    # 步骤 id -> 实例（兼容 step_id 引用）
}
```

- **每个源码内置节点必须在 `_STEPS` 注册**，否则 worker 执行时报 `ValueError: 未知工作流节点: <id>`（`_run_node` 中 `get_step_instance` 返回 None）。节点管理器自定义节点由 `custom_node_runtime.py` 处理，不适用本节。
- 建议同时注册 **节点类型 id** 和 **步骤 id** 两个 key（与现有节点保持一致），保证新旧引用都能解析。
- 导入语句放在文件顶部，与既有 import 风格一致。
- 完成后验证：`get_step_instance("my_node")` 不返回 None。

## 5. 子进程隔离节点（execution_domain="process"）额外规范

### 5.1 执行流程

父线程（`workflow_runtime._run_node_subprocess`）以子进程方式调用：
```
python -m backend.control_plane.step_worker <args.json>
```
`step_worker` 读取 args.json 后：`get_step_instance(node_type)` → 注入 `_node_id/_node_config/_step_inputs` → 调 `step.run()` → pickle 结果写回 `result_path`。

### 5.2 结果与进度回传

- 结果：`step.run` 返回 dict，pickle 写回 result_path，父线程读取。
- 进度：callback 写 stdout 行 `@PROGRESS@|<pct>|<msg>`，父线程逐行解析；**中文不乱码依赖 UTF-8**（step_worker 已强制）。
- 步骤内 `print` 也会进入 stdout，请勿输出非 `@PROGRESS@` 前缀的关键信息（父线程只解析该前缀）。

### 5.3 协作取消

callback 会检查取消标记文件（`cancel_file`），存在则抛 `TaskCancelledError`。**步骤内耗时循环应定期调用 callback**，否则取消只能靠父进程 kill 进程树兜底（能停但不算优雅）。

## 6. 产物命名与下游引用规范（重要）

### 6.1 产物文件名必须带节点唯一 id

> 同一节点类型可能在一个工作流中出现多次，为避免文件互相覆盖，**输出文件名必须包含节点 id 后缀**。

命名格式：`{base}_{node_id}.{ext}`，例如：

```python
node_id = getattr(self, "_node_id", "")
output_path = os.path.join(task_dir, "cache", f"my_result_{node_id}.json")
```

- `outputs` 里端口值也用带 `node_id` 的路径。
- `check_artifact` / 下游查找产物时用 `find_artifact` 忽略 node_id 后缀匹配。

### 6.2 下游查找用 find_artifact

```python
from backend.steps.base_step import find_artifact
path = find_artifact(os.path.join(task_dir, "output"), "extracted_audio.wav")
```

`find_artifact(directory, base_name)` 匹配规则：
- 精确匹配 `base.ext` 或 `base_<任意后缀>.ext`
- 匹配到多个时取排序后第一个（无 node_id 后缀的优先）
- 找不到返回 `None`

### 6.3 目录约定

- 中间产物 → `task_dir/cache/`
- 最终输出产物 → `task_dir/output/`
- 输入节点复制到任务目录后：`input_video.<ext>` / `input_audio.<ext>` / `input_subtitle.<ext>`

## 7. 输入注入规范（忠实于连线）

- 运行时 `_resolve_step_inputs` 会从**上游节点在 DB 中的 outputs** 按端口 id 注入到 `self._step_inputs`。
- 步骤内读取连线输入统一用 `self._step_inputs.get("<端口id>", "")`（端口 id = builtin_node_types 里 inputs 的 id）。
- 传入的路径可能是**相对路径**（相对 task_dir）也可能是绝对路径：解析时先判 `os.path.isabs`，否则 `os.path.join(task_dir, raw)`。
- 节点自身多余的输入需求（不来自连线的）按 6 的产物约定在任务目录中查找，属于节点内部逻辑，与连线注入互不影响。
- 典型读取模式（参考 `s15_extract_audio` / `s_video_frame_extract`）：

```python
step_inputs = getattr(self, "_step_inputs", {}) or {}
video_input = step_inputs.get("video", "")
if video_input:
    p = video_input if os.path.isabs(video_input) else os.path.join(task_dir, video_input)
    if os.path.exists(p):
        video_path = p
# 无连线时回退扫描 cache/input_video* 或 cache 下视频
```

## 8. 前端同步规范

- 前端默认从后端拉取节点类型（`/api/node-types`），**新增节点后无需改前端即可显示**（只要后端 builtin_node_types 有定义）。
- 兜底副本 `frontend/src/lib/fallbackNodeTypes.ts`（注释标明"Generated from backend/config/builtin_node_types.py"）：后端 API 不可用时前端依赖它，**建议**新增节点时同步追加对应定义，保持两端一致（字段：id/name/category/description/icon/color/inputs/outputs/defaultConfig/configFields）。
- 前端 `NodeTypeDef` 结构见 `frontend/src/lib/workflowTypes.ts`；端口 type 必须是 `PortType` 之一（见 3.2）。

## 9. 新建节点的完整操作清单（Checklist）

- [ ] **① builtin_node_types.py**：追加节点 dict（id/name/execution_domain/category/icon/color/inputs/outputs/defaultConfig/configFields），端口 type 对齐 PortType
- [ ] **② 步骤文件**：在 `backend/steps/` 新建 `s_<id>.py`，类继承 `BaseStep`，实现 `check_artifact` / `validate_inputs` / `run`，输出产物带 `{node_id}` 后缀，产出 `{"artifacts", "outputs"}`
- [ ] **③ step_registry.py**：import 步骤类并注册 `"<id>"` 与 `"s_<id>"` 两个 key
- [ ] **④（建议）fallbackNodeTypes.ts**：同步前端兜底定义
- [ ] 执行域判定：重节点/网络节点标 `"process"`，并确认步骤回调进度、支持协作取消；轻节点标 `"thread"`
- [ ] 验证：`get_step_instance("<id>")` 非 None；`python -m py_compile` 通过；前端 palette 出现该节点
- [ ] 端到端：工作流中放置该节点，执行后产物出现在任务目录、节点状态正常推进（running→completed）、失败有明确错误信息
- [ ] （可选）分享到共享社区：`pack-node` → `publish`，并在社区页确认可被导入

## 10. 分享到共享社区（可选）

- 自定义节点可通过「共享社区」打包发布：`POST /api/community/pack-node` 生成资源包（node_config + code + 预览图）→ `POST /api/community/publish` 上传到云端 Worker（R2 + D1 元数据）；其他人用 `import-workflow`/节点管理器导入即可安装使用。
- 打包时节点定义会被**净化**（去掉本地私密信息），发布前请确认 `configFields` 中没有机器相关绝对路径等敏感默认值。
- 社区 Worker 地址由前端构建时注入（`VITE_COMMUNITY_API_URL`），无需用户配置；发布为公开接口但有限频与大小限制。

## 11. 常见错误与排查

| 错误 | 原因 | 修复 |
|---|---|---|
| `ValueError: 未知工作流节点: xxx` | 节点类型 id 未在 step_registry 注册 | 按第 4 节注册（并重启 worker） |
| `(trapped) error reading bcrypt version` | passlib/bcrypt 版本兼容 | 无害警告，已加补丁，忽略 |
| 下游找不到产物 | 产物未带 node_id 后缀 或 命名与 find_artifact 约定不符 | 按第 6 节命名，用 find_artifact 匹配 |
| 节点执行后无进度/状态不更新 | WS 事件未推送到前端（后端进程崩溃或路由不匹配） | 确认后端存活、`/ws/tasks/{id}` 可连；重启后端+worker |
| process 节点取消不生效 | 步骤耗时循环未调用 callback | 循环内定期 callback 检查取消标记 |
